# 生成周计划

用户传入周次（W5 或 W6），你需要读取对应文档、拆分为 7 天计划、生成文件。

## 周次→文档映射

| 周次 | 文档路径 | 主题 |
|---|---|---|
| W5 | `docs/06-deployment.md` | Docker 部署 + Streamlit 前端 |
| W6 | `docs/07-interview-showcase.md` | 集成测试 + 面试准备 |

## 执行步骤

### 1. 读取文档

完整读取该周对应的 docs/ 文档。禁止猜测内容。

### 2. 提取结构

从文档中提取：
- §1 概念学习章节的所有小节标题
- §4 分步实现方案的所有 Step 编号和标题
- §5 测试方案的内容
- §6 面试要点的问题列表

### 3. 按 7 天自适应分配

约束：每天 3-4 小时。

分配原则（不是固定模板，按实际内容灵活调整）：
- 按 Step 之间的依赖关系分组，有前置依赖的不能提前
- 复杂 Step 独占一天，简单 Step 可合并
- 概念学习穿插在对应编码任务的同一天
- D7 必须包含面试问题复习（引用 §6）+ 端到端验证

### 4. 生成周概览文件

路径：`Today_Plan/Each_Week/W{N}-daily-plan.md`

格式模板（与 W1-W3 一致）：

```markdown
# W{N} 日计划概览（Doc XX：主题名）

每天 3-4 小时。[一句话描述本周核心目标和技术路线]

| 天 | 学习内容（概念/原理） | 编码任务（对应 Doc XX 的 Step） | 产出物 |
|:---:|---|---|---|
| **D1** | [引用文档章节号] | **Step X**：[具体任务描述] | [可执行验证命令] |
| ... | ... | ... | ... |
```

要求：
- 学习内容必须引用文档具体章节号（如 "Doc 06 §1 'Docker 基础'"）
- 编码任务必须引用 Step 号（如 "Step 3：编写 docker-compose.yml"）
- 产出物必须是可执行的验证命令（pytest / curl / docker / python -c）

### 5. 生成 7 个每日执行文件

路径：`Today_Plan/W{N}/D1.md` ~ `D7.md`

每个文件格式：

```markdown
# W{N}-D{X}：[简短标题]

## 今日概览

| 项目 | 内容 |
|---|---|
| **学习主题** | [主题名] |
| **对应文档** | Doc XX §Y "[章节名]" |
| **编码任务** | Doc XX Step Z |
| **预计时长** | 3-4 小时 |

---

## 学习内容（~1 小时）

阅读 Doc XX §Y 的以下部分：
1. **[小节标题]** — [一句话说明要理解什么]
2. ...

重点理解：
- [关键概念 1]
- [关键概念 2]

---

## 编码任务

### 任务 1：[任务名]（Doc XX Step Z）

[具体实现指引：文件路径、代码结构、关键字段]

**验证**：[可执行命令]

### 任务 2：...

---

## 验收标准

- [ ] [可执行验证命令 1]
- [ ] [可执行验证命令 2]
- [ ] ...
```

### 6. 更新 6-week-plan.md

读取 `Today_Plan/Overall_Plan/6-week-plan.md`，将末尾的：
> W1-W4 日计划见 `Today_Plan/Each_Week/`，W5-W6 待 W4 完成后展开。

更新为反映已生成状态，例如：
> W1-W5 日计划见 `Today_Plan/Each_Week/`，W6 待 W5 完成后展开。

或如果 W5、W6 都已生成：
> W1-W6 日计划见 `Today_Plan/Each_Week/`。

## 质量红线

- 每个编码任务都必须能追溯到文档的具体 Step
- 每个学习内容都必须引用文档章节号
- 每个产出物都必须是可执行的验证命令（禁止"代码能跑"这类模糊描述）
- D7 必须包含面试问题复习
- 先读文档再生成，不猜测

## 输出

生成完毕后，列出所有创建/修改的文件路径供用户确认。

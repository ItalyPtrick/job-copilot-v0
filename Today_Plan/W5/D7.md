## 学习内容（~1h）

复习 Doc 06 §6 面试要点，确保能流畅回答：

### 必须能答的 3 个问题

1. **Q: 你的项目是怎么部署的？**
   > Docker Compose 一键部署。4 个服务：FastAPI API、Celery Worker、PostgreSQL、Redis。服务间通过 Docker 内部网络通信，数据通过 Volume 持久化。

2. **Q: 为什么用 Docker 而不是直接部署？**
   > 环境一致性 + 一条命令启动所有依赖 + healthcheck 确保启动顺序 + 面试演示随时可用。

3. **Q: Docker 部署中遇到过什么问题？**
   > (1) 服务启动顺序——healthcheck + depends_on；(2) 数据持久化——Volume 挂载；(3) 网络——容器内用服务名而非 localhost。

### 4 个能讲的亮点

1. 一键启动：`docker compose up -d`
2. 健康检查：PostgreSQL 和 Redis 的 healthcheck
3. 数据持久化：Volume 挂载
4. 开发/生产分离：dev 配置只启动依赖

## 编码任务

### 任务 1：完整演示流程验证

```powershell
# 1. 一键启动
docker compose up -d --build

# 2. 等待所有服务 healthy
docker compose ps

# 3. 执行迁移
docker compose exec api alembic upgrade head

# 4. 验证各端点
curl http://localhost:8000/
curl -X POST http://localhost:8000/interview/start -H "Content-Type: application/json" -d '{"skill":"python_backend"}'
curl -X POST http://localhost:8000/resume/upload -F "file=@tests/fixtures/test_resume.txt"

# 5. Streamlit 演示
streamlit run ui/app.py
# 在浏览器中走一遍三个功能页面

# 6. 清理
docker compose down
```

### 任务 4：记录设计决策

更新 `docs/design-decisions.md`，新增 W5 决策：

- **为什么用 Docker Compose 而非 K8s？**
  项目规模小，Compose 足够；面试演示一条命令启动比 K8s 集群更实际
- **为什么开发环境只容器化基础设施？**
  应用本地跑方便热重载和断点调试
- **PostgreSQL 切换策略**
  通过环境变量切换，本地开发仍可用 SQLite，Docker 部署用 PostgreSQL

### 任务 5：全量测试

```powershell
# 本地全量测试（SQLite 模式）
pytest tests/ -v

# 容器内全量测试（PostgreSQL 模式）
docker compose up -d
docker compose exec api pytest tests/ -v
docker compose down
```

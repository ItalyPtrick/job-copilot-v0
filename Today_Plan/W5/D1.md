1. **为什么需要 Docker？** — 理解容器化解决的 4 个问题（环境一致性、依赖管理、演示稳定性、多服务协调）

3. **本项目的服务架构** — 理解 4 服务（api + worker + redis + postgres）+ 4 个 Volume 的设计

重点理解：
- Dockerfile 是构建镜像的脚本，每条指令生成一层
- Docker Compose 定义多容器应用的拓扑（服务、网络、卷）
- Volume 是容器外的持久化存储，容器删除后数据不丢
- `python:3.11-slim` 比完整版小 ~800MB，够用

## 编码任务

### 任务 1：安装 Docker Desktop

确认 Docker Desktop 已安装并运行：

```powershell
docker --version
docker compose version
```

### 任务 2：编写 Dockerfile（Doc 06 Step 1）

在项目根目录创建 `Dockerfile`：

```dockerfile
FROM python:3.11-slim

WORKDIR /app

# 系统依赖（PyMuPDF、psycopg2 需要）
RUN apt-get update && apt-get install -y --no-install-recommends \
    gcc \
    libpq-dev \
    && rm -rf /var/lib/apt/lists/*

# 先复制依赖文件，利用 Docker 层缓存
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 复制应用代码
COPY . .

EXPOSE 8000

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

关键设计决策：
- 先 COPY requirements.txt 再 COPY . → 代码改动不会重新安装依赖（层缓存）
- `--no-cache-dir` → 减小镜像体积
- `--no-install-recommends` → 只装必要系统包

### 任务 3：验证构建

如果 `requirements.txt` 来自 Windows/conda 导出且是 UTF-16 编码，先转成 UTF-8（否则容器内 `pip install -r requirements.txt` 会失败）。

```powershell
python -c "from pathlib import Path; p=Path('requirements.txt'); b=p.read_bytes(); s=b.decode('utf-16-le') if b[:200].count(b'\0') else b.decode('utf-8'); p.write_text(s, encoding='utf-8')"
docker build -t job-copilot .
docker run --rm job-copilot python -c "import app; print('OK')"
```

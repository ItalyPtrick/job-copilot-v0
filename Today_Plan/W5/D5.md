## 学习内容（~30 分钟）

### 容器化测试策略

两种测试方式：
1. **容器内跑测试**：`docker compose exec api pytest tests/ -v` — 验证容器环境下代码正常
2. **从宿主机测试 API**：`curl http://localhost:8000/...` — 验证端口映射和网络

### 数据持久化验证

Volume 的意义：容器删除重建后数据不丢。验证方法：
1. 写入数据
2. `docker compose down`（不加 `-v`）
3. `docker compose up -d`
4. 确认数据仍在

### 容器内调试

```bash
# 进入容器 shell
docker compose exec api bash

# 查看环境变量
docker compose exec api env | grep DATABASE

# Python REPL
docker compose exec api python
```

## 编码任务

### 任务 1：容器内全量测试

```powershell
# 确保服务运行
docker compose up -d

# 等待 healthy
docker compose ps

# 执行测试
docker compose exec api pytest tests/ -v
```

如果有测试失败，排查原因（常见问题：Redis 连接地址、数据库 URL、文件路径差异）。

### 任务 2：API 端点验证

逐一验证所有模块的核心端点：

```powershell
# 根路径
curl http://localhost:8000/

# 知识库
curl -X POST http://localhost:8000/kb/query -H "Content-Type: application/json" -d '{"question":"test"}'

# 面试（需要 Redis）
curl -X POST http://localhost:8000/interview/start -H "Content-Type: application/json" -d '{"skill":"python_backend"}'

# 简历上传
curl -X POST http://localhost:8000/resume/upload -F "file=@tests/fixtures/test_resume.txt"
```

### 任务 3：数据持久化验证

```powershell
# 1. 通过 API 写入数据（上传简历或创建面试 session）
curl -X POST http://localhost:8000/resume/upload -F "file=@tests/fixtures/test_resume.txt"

# 2. 记录返回的 ID

# 3. 停止服务（保留 Volume）
docker compose down

# 4. 重新启动
docker compose up -d

# 5. 查询之前的数据是否还在
curl http://localhost:8000/resume/{id}/status
```

### 任务 4：修复容器环境问题

常见需要修复的问题：
- 测试中硬编码了 `localhost` Redis 地址 → 改为从环境变量读取
- 文件上传路径在容器内不存在 → 确保 Volume 挂载正确
- Alembic 迁移脚本中硬编码 SQLite URL → 改为动态读取
- 字体文件路径（ReportLab）→ 容器内需要安装或挂载字体

逐一修复直到全量测试通过。

## 验收标准

- [x] `docker compose exec api pytest tests/ -v` 全绿
- [x] `curl http://localhost:8000/` 返回成功
- [x] 知识库、面试、简历三个模块的核心端点均可调用（不报 500）
- [x] 数据持久化验证通过：down → up 后数据仍在
- [x] 容器日志无 ERROR 级别输出：`docker compose logs api --tail=50`

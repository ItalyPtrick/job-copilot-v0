## 学习内容（~30 分钟）

### Docker Compose 核心

- `services`：定义每个容器的配置（镜像、端口、环境变量、依赖）
- `depends_on` + `condition: service_healthy`：控制启动顺序
- `healthcheck`：定期检测服务是否就绪（不只是"启动了"，而是"能接受请求了"）
- `volumes`：命名卷持久化数据，容器重建不丢失

### 服务间通信

容器内用**服务名**作为主机名（不是 localhost）：
- API 连接数据库：`postgresql://postgres:postgres@postgres:5432/job_copilot`
- API 连接 Redis：`redis://redis:6379/0`

**面试怎么讲**："Compose 创建了一个内部网络，服务之间用服务名做 DNS 解析。API 容器里 `postgres` 这个主机名会解析到 PostgreSQL 容器的 IP。"

### 任务 2：编写 docker-compose.yml（Doc 06 Step 3）

在项目根目录创建 `docker-compose.yml`，包含 4 个服务：

| 服务 | 镜像 | 端口 | 说明 |
|---|---|---|---|
| api | 本地构建 | 8000:8000 | FastAPI 主服务 |
| worker | 本地构建 | — | Celery Worker |
| postgres | postgres:16-alpine | 5432:5432 | 数据库 |
| redis | redis:7-alpine | 6379:6379 | 缓存 + Broker |

关键配置点：
- api 和 worker 共用同一个 Dockerfile，worker 覆盖 `command`
- postgres 和 redis 都配 healthcheck
- api/worker 的 `depends_on` 使用 `condition: service_healthy`
- 4 个命名卷：`pg_data` / `redis_data` / `upload_data` / `chroma_data`
- 环境变量通过 `environment` 覆盖 `.env` 中的本地值

参考 Doc 06 Step 3 的完整 YAML。

### 任务 3：验证配置

```powershell
# 语法检查
docker compose config

# 启动所有服务
docker compose up -d

# 检查状态（等待 healthy）
docker compose ps

# 查看日志确认无报错
docker compose logs api --tail=20
docker compose logs worker --tail=20
```

### 任务 4：验证服务连通性

```powershell
# API 可达
curl http://localhost:8000/

# Redis 可达
docker compose exec redis redis-cli ping

# PostgreSQL 可达
docker compose exec postgres pg_isready -U postgres
```
